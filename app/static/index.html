    Jobs
    
          
    Automations as DAGs, like Apache Airflow: triggers say when a DAG runs (a schedule,
            a full disk, a new device, new mail…) and tasks say what it does (send an email, run a command, ask the AI…),
            in the order their connections give. Tasks that don't depend on each other run at the same time.
    
        
    
        
      
    
      
    
    
    
  
    

  
    
    
    
      
      
    
        
    
          
    
          
    
        
    
        
    
      
    
      
    
        
        
        
      
    
      
    
    
    
  
    

  
    
    
    
      
    
        
        
    New DAG
    
        
        
    
          
          
        
    
        
        
      
    
      
    
      
    
        
    
          
          
          
          
        
    
        
    
          Triggers — when it runs (any of them). None = only when you start it.
          
    
          
        
    
        
    
          
    
          
    
            
    
            
    
              
            
    
            
    Drag operators here from the list (or click one) to add tasks. Connect a task's
              right dot to another task's left dot: the second one runs after the first.
    
          
    
          
    
        
    
      
    
      
    
        
    The DAG as Airflow-style Python. Edit it and switch back to Graph (or save) to apply. It's read, never run:
          only plain values, tasks.<operator>(…) calls and a >> b dependencies are allowed.
    
        
      
    
    
    
  
    

  
  
    
    
    
      
    
        
    
          
    Processes
    
          
    SysAdmin.IA runs as separate processes, so one part can stop or crash without taking the others down.
            A crashed process is restarted automatically; one stopped here stays stopped (also after a reboot) until you start it.
    
        
    
        
      
    
      
    
      
    
    
    
  
    

  
  
    
    
    
      
    
        
    
          
    Variables
    
          
    Values you define once and reuse anywhere, e.g. an alert address. In a job, type
            {{var.name}} and it's replaced by the value. Secret variables are hidden after saving and masked in logs.
    
        
    
        
      
    
      
    
      
    
        
    Monitor values 
    
        
    Live measurements from this server, read at the moment a job uses them — e.g.
          CPU at {{mon.cpu_percent}}% or {{mon.temp_max_sensor}} is {{mon.temp_max}} °C. Click a name to copy it.
    
        
    
      
    
      
    
        
    Built-in values
    
        
    Always available, no need to create them. Shown with their current value.
